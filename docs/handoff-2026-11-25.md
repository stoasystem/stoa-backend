## 6. 工作方式

- **没有 PR CI。** 合并到 main 就跑 lint、测试并部署到生产，本机测试是唯一的合并前检查。一次合一个 PR，等 "Deploy Backend to Production" 跑完、读到结论再合下一个。合并要用户同意。
- **本机跑测试**：`env -u AWS_PROFILE PYTHONUTF8=1 AWS_SHARED_CREDENTIALS_FILE=/nonexistent AWS_CONFIG_FILE=/nonexistent .venv/Scripts/python -m pytest ... --force-enable-socket --continue-on-collection-errors`。本机在 main 上也有约 15 个失败和 7 个收集错误，要和一个**没人在改**的 main 工作区的基线逐条比较。
- **worktree 里重新生成** `docs/api/openapi.json` 或路由清单要设 `PYTHONPATH="$W/src;$W"`（`W="$(pwd -W)"`），否则生成器用的是主 checkout 的代码。文件用 LF，写文件时 `newline="\n"`。合并前跑整棵树的 `ruff check src tests scripts`。
- **叠起来的 PR**：仓库不会在合并时自动删分支；合下层 PR 时不要加 `--delete-branch`，否则上层 PR 会被关掉。
- **生产操作**：运维脚本默认 `--profile stoa`。由 agent 给用户一条不需要密码的 PowerShell 命令，用户跑，agent 读终端结果。SSO 过期时请用户跑 `aws sso login --sso-session stoa`。stoa-admin MCP 的改数据工具先 `dryRun=true` 给用户看，确认后再正式执行。
- **规划只放在 issue 里**：地图、拆单、决定记录都写进 GitHub issue。拷问单（`wayfinder:grilling`）一次问用户一个问题、附推荐，定下后在工单里写「定下的形状」、改成 `wayfinder:task`、拆子单。
- **跟用户说话**：用中文；提到工单时写名字，编号放括号里，例如「附件离开第 1 步（#653）」，不要只写编号。
- 更多约定：`CLAUDE.md`、`docs/conventions.md`、`CONTEXT.md`、`docs/agents/`。
