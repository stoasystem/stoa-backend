## Question

完整业务写入、Stripe test mode、账号删除、恢复和负载测试使用独立环境，还是当前线上专用测试环境？当前线上允许的合成账号和操作边界是什么？若暂时不能使用云端真实环境，哪些验收必须保持未验证？

需要由用户说明环境的实际用途和期望范围，历史“没有真实用户”陈述不能代替本次决定。建议：独立环境做完整测试，当前线上只做有限合成冒烟。参考讨论草案的环境预检证据，尤其只改 API URL 无法隔离固定 Cognito client 和默认 DynamoDB 表。

## Answer

2026-09-05 用户实时批准：采用“独立测试环境做完整测试，当前线上只做合成账号的有限冒烟”。

- 独立测试环境是完整业务写入、Stripe test mode、账号删除、恢复、并发及有限负载测试的唯一目标；其测试数据必须为受控合成数据。
- 当前线上仅可使用受控合成账号执行有限核心冒烟；不得把该冒烟扩展为支付、删除、恢复或负载验证，也不得触及真实用户数据。
- 独立环境不可用时，上述完整验收保持未验证（不得由线上冒烟、mock 或历史报告替代）。

该边界仅确定后续测试规划的目标环境与证据级别；本轮没有运行测试、进行云端写入、部署或创建定时任务。
