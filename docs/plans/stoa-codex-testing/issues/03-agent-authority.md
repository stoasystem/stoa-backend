## Question

未来启用流程后，Codex 默认仅测试和报告，还是允许在隔离分支补回归用例并生成修复 patch？合成数据初始化与清理、外部通知、PR 发布、自动合并和部署分别在哪一步需要额外授权？

建议测试与分析自动执行，修复最多生成可审查 patch；合并/部署保持现有授权边界。权限设计须能在 runner 与云身份层落实，不能只依靠 prompt。此问题决定未来运行权限，不回溯扩大本轮仅规划的授权。

## Answer

Codex 的自动执行范围限定为运行测试并记录遇到的问题。该决定取代上文允许生成修复 patch 的建议。

- 使用既有测试入口，在已批准的环境和功能范围内执行；记录失败步骤、预期与实际结果、可复现条件及脱敏证据。
- 不修改业务代码、测试代码、断言、配置或门禁，不生成或应用修复 patch。
- 如现有测试缺失、准备条件不足或必须修改才能继续，记录缺口或阻塞及其影响；不得把未执行项记为通过。
- 自动权限不包含额外的数据初始化/清理操作、外部通知、PR 发布、合并或部署。既有测试内的合成数据操作仍受已批准的环境边界约束。

本决议定义后续测试运行权限；规划票据和测试问题记录可按本流程维护。
