## 7. 工作方式

和 `docs/handoff-2026-11-25.md` 第 6 节相同，要点：

- **没有 PR CI。** 合并到 main 就跑 lint、测试并部署到生产。一次合一个 PR，等 "Deploy Backend to Production" 跑完、读到结论再合下一个。合并要用户同意。
- **本机测试**要和一个**没人在改**的 main worktree 的基线逐条比较。现在 main 上本机约 14 个失败、7 个收集错误（worktree 里可能更多）。
- **worktree 里重新生成** OpenAPI 或路由清单要设 `PYTHONPATH="$W/src;$W"`；否则 `test_openapi_snapshot.py::test_check_mode_fails_on_a_stale_snapshot` 会在 worktree 里假失败。
- **叠起来的 PR**：合下层 PR 时不要加 `--delete-branch`。
- **生产操作**：运维脚本默认 `--profile stoa`，agent 给用户一条不需要密码的 PowerShell 命令，用户跑，agent 读终端。stoa-admin MCP 的改数据工具先 `dryRun=true`。
- **规划只放在 issue 里**；跟用户说中文，提到工单写名字、编号放括号里。
