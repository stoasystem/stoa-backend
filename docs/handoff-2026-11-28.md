## 6. 工作方式

- **后端没有 PR CI。** 合并到 main 就跑 lint、测试并部署到生产。一次合一个 PR，等 "Deploy Backend to Production" 跑完、读到结论再合下一个。合并要用户同意。前端和官网同样是合并即部署。
- **后端本机测试**要和一个**没人在改**的 main worktree 的基线逐条比较。在 worktree 里重新生成 OpenAPI 或路由清单要设 `PYTHONPATH="$W/src;$W"`。
- **叠起来的 PR**：合下层 PR 时不要加 `--delete-branch`。
- **生产操作**：运维脚本默认 `--profile stoa`，agent 给用户一条不需要密码的 PowerShell 命令，用户跑，agent 读终端。stoa-admin MCP 的改数据工具先 `dryRun=true`。
- **清理本地前**先查有没有会话在用（会话列表、`git worktree list` 里的 locked、临时目录里的新 worktree）。11-28 清理时误删过一个刚建的检查 worktree。
- **规划只放在 issue 里**；跟用户说中文，提到工单写名字、编号放括号里。
- 更多约定：各仓库的 `CLAUDE.md`、后端的 `docs/conventions.md`、`CONTEXT.md`、`docs/agents/`。
