# STOA 首轮测试执行规范

日期：2026-09-05。状态：依据已批准决议整理，首轮尚未执行；性能门槛仍待基线后确定。

本文件是执行步骤汇总。决策详情以[决策地图](../../.scratch/stoa-codex-testing/map.md)链接的票据 Answer 为准；[历史讨论草案](STOA_CODEX_AUTOMATED_TEST_PLAN.md)用于查找既有入口和调查线索，其建议不自动成为执行要求。

## 首轮范围

独立测试环境使用受控合成数据，覆盖登录与角色、聊天与上传、真人老师完整答疑、家长周报、练习复习、权限和账号删除。支付（含关闭态及 Stripe test mode）、原生移动端、Demo 能力不纳入。当前线上仅允许受控合成账号的有限核心冒烟；独立环境不可用时，完整验收保持未验证，不转移到线上执行。

Codex 仅运行既有测试并记录问题，不修改业务代码、测试代码、断言、配置或门禁，不生成修复 patch。缺少入口、凭据、数据准备或费用控制能力时记录阻塞。额外的数据初始化/清理、外部通知、PR、合并、部署不属于自动权限。

## 运行约束

- 手动触发一轮；核心流程逐个执行，每个流程计划三次，保留学生与老师的完整交互，不额外自动重跑。
- 整轮最多 60 分钟，停止时保留结果，未完成项记为未验证。该时限不是产品响应或恢复门槛。
- AWS 与模型调用新增费用合计最多 5 美元；Codex 使用现有额度。运行前核实既有入口能否可靠限制费用，不能控制的付费项目记为阻塞。
- 普通失败记录后继续不受影响的流程；发现越权、数据泄露、丢消息或重复扣额度立即停止本轮。

## 执行顺序与记录

1. **固定输入与预检。** 记录四仓库提交、未提交差异、测试入口与预期用例集合。核对独立环境的 API/Web、身份、存储和实际部署版本，核对既有超时、重试及费用控制。工作区改动必须保留；需要修改才能运行的项目记录阻塞。
2. **既有本地检查。** backend、frontend、infra 分别使用当前可用入口运行适用检查；docs 用于对照产品要求。先核对测试收集集合，确保排除支付，不通过执行部署工作流获取测试结果。历史草案中的命令需要按本轮候选检查后使用。
3. **真实核心流程。** 在预检通过的独立环境，按首轮范围逐个完成三次计划执行。每次记录实际角色交互、耗时、错误和恢复结果；受剩余时间、费用和停止条件约束。无法运行的流程保留明确原因。
4. **汇总与交付。** backend 的 `.scratch/stoa-codex-testing/runs/<run_id>/` 统一保存报告与脱敏证据，在当前任务汇报问题。报告包含候选版本、实际环境/服务版本、命令、起止时间、退出码、用例计数及每次尝试；每个问题包含复现步骤、预期与实际结果、证据路径和影响。不得保存密码、token、Cookie 或真实用户正文。

## 结果判定

| 状态 | 使用条件 |
|---|---|
| PASS | 该必需用例本轮实际执行并满足断言 |
| FAIL | 断言失败；保留实际问题与复现证据 |
| 未验证 / BLOCKED | 缺测、跳过、零用例、环境不可用、版本证据不足、费用不可控或时限内未完成 |
| FLAKY | 首次失败、后续尝试通过；保留所有尝试，不将首败抹去 |
| 范围外 | 支付、原生移动端和 Demo；不计入通过数量 |

已确认范围的必需功能与安全用例全部实际通过且环境、版本可核对，才报告功能与安全整体通过。越权、数据泄露、重复扣额度或可达高危漏洞阻止整体通过；AI 评分争议留待人工核验。

性能结论保持待定：草案时间仅作参考，超出记录问题。三次运行用于初步观察，不证明可靠的 p95/p99、并发容量或长期稳定性。
